# SCA Implementation Roadmap

## Delivery Principle

Build the permanent provenance platform in controlled layers. The current VPS is temporary. Every phase must preserve portability to a future permanent server.

Each implementation phase is broken into small Claude tasks. ChatGPT audits each completed task before the next task is issued.

## Phase 0 — Architecture Freeze

**Goal:** lock the rules before product code.

Decisions now accepted:

- greenfield rebuild; do not recover old Ownership Bridge;
- current VPS is temporary construction/staging infrastructure;
- implementation source belongs in a separate private Git repository;
- TypeScript + Node.js + Next.js + PostgreSQL + Prisma + Docker;
- modular monolith first;
- Shopify remains commerce source;
- SCA remains provenance/ownership source;
- QR identity is generated by SCA, not Shopify;
- permanent QR uses a Jeremy-controlled domain, never a temporary IP/hostname;
- Shopify purchase = eligible to claim;
- SCA scan/login/claim = registered owner;
- ownership/service/transfer history is append-only;
- migration to permanent infrastructure is a design requirement from day one.

**Status:** ACCEPTED via ADR-0005 and infrastructure blueprint.

## Phase 1 — Portable Application Foundation

**Goal:** prove we can build, run, test, back up, and later move the application before feature development accelerates.

Deliverables:

- private implementation repository;
- Next.js/TypeScript application shell;
- Prisma + PostgreSQL baseline;
- Dockerfile and Docker Compose;
- environment schema/example with no secrets committed;
- application health endpoint;
- database readiness check;
- baseline lint/typecheck/test scripts;
- initial migration workflow;
- non-root runtime where practical;
- temporary VPS deployment/runbook;
- backup/restore skeleton;
- repository/deployment documentation.

Exit proof:

- fresh clone builds;
- containers start;
- health check passes;
- application connects to PostgreSQL;
- migration runs safely;
- no hard-coded temporary server address;
- clean shutdown/restart works.

## Phase 2 — Core Provenance Domain

**Goal:** build the permanent data model and item lifecycle.

Core entities:

- `collector_accounts`
- `eyewear_items`
- `authentications`
- `ownership_events`
- `transfer_requests`
- `service_events`
- `status_events`
- `shopify_sale_links`
- `qr_identifiers`

Core state flow:

```text
UNCLAIMED
  -> SOLD_AWAITING_CLAIM
  -> REGISTERED
  -> TRANSFER_PENDING
  -> REGISTERED (new owner; old history retained)
```

Also design explicit cancellation/refund/return behavior and idempotency.

Exit proof:

- migrations and constraints exist;
- one physical pair can be represented independently of a Shopify product definition;
- append-only event history is enforced and tested;
- duplicate active ownership/claim conditions are blocked.

## Phase 3 — SCA Admin / CRM

**Goal:** allow Jeremy's team to create and manage certified physical eyewear records.

Initial functions:

- admin authentication and roles;
- create/search eyewear records;
- assign Certification ID;
- map Shopify product/variant/SKU references;
- record authentication result;
- record condition grade and notes;
- upload inspection media;
- create QR identity;
- view claim/ownership status;
- view event history;
- basic collector/customer lookup.

Later admin modules add transfers, services, lost/stolen, reports, and analytics.

## Phase 4 — Permanent QR + Public Registry

**Goal:** make every certified physical pair resolvable through a stable public identity.

Deliverables:

- immutable/stable QR identifier;
- public registry route;
- environment-driven QR base URL;
- explicit public-field allowlist;
- state-sensitive public display;
- non-production watermark/guard for staging QR;
- QR print/export action for staff.

Permanent QR printing is not enabled until a Jeremy-controlled production URL is configured.

## Phase 5 — Shopify Integration

**Goal:** connect the real Second Chance Eyewear commerce flow to exact SCA physical items.

Initial scope baseline:

- `read_products`
- `read_inventory`
- `read_orders`
- `read_customers`

Deliverables:

- real store identity recorded before production connection;
- Shopify app OAuth/configuration;
- signed webhook verification;
- paid-order processing;
- cancellation/refund/return-aware eligibility;
- idempotent sale-link creation;
- explicit mapping from order line to exact `eyewear_item`;
- app-uninstalled handling;
- audit logs and safe retries.

No Shopify write scope unless separately approved.

## Phase 6 — Collector Accounts, Claim, and My Collection

**Goal:** complete the customer ownership-registration experience.

Flow:

1. customer receives physical eyewear and printed SCA QR;
2. scans QR;
3. sees authenticated provenance record and Claim CTA when eligible;
4. signs in or creates an independent SCA collector account;
5. SCA verifies claim eligibility;
6. ownership event is appended;
7. state becomes `REGISTERED`;
8. item appears in My Collection.

Emailing the same QR/claim link may be added as convenience. Checkout is not the ownership-registration event.

## Phase 7 — Ownership Transfer

**Goal:** support real resale/gifting without erasing provenance.

Deliverables:

- owner initiates transfer;
- secure transfer token/workflow;
- recipient accepts after authentication;
- transfer expires/cancels safely;
- new ownership event appended;
- prior owner remains in history;
- current owner is derived from active state.

## Phase 8 — Service + Lost/Stolen Registry

**Goal:** extend the permanent record through post-sale life.

Deliverables:

- append-only service events;
- repair/lens/polish/tune-up/inspection records;
- lost status;
- stolen status;
- recovered status;
- public warning without private owner data;
- admin audit trail.

## Phase 9 — Certificates and Insurance Records

**Goal:** produce durable documents from trusted registry data.

Deliverables:

- authentication certificate;
- ownership certificate;
- provenance report;
- insurance report PDF;
- controlled inclusion of photos/specs/condition/current ownership;
- versioned document generation and audit record.

## Phase 10 — Permanent Infrastructure Migration

**Goal:** move from temporary shelter to permanent SCA infrastructure without rebuilding the product.

Deliverables:

- permanent server hardening;
- production PostgreSQL/backup strategy;
- durable object storage;
- production secrets;
- Jeremy-controlled production QR domain;
- full restore rehearsal;
- smoke tests;
- DNS cutover;
- rollback window;
- temporary VPS decommission only after acceptance.

Permanent QR identifiers and ownership history must survive unchanged.

## Phase 11 — Expansion

After the core registry is reliable:

- market history;
- resale-value tracking (not formal appraisal);
- market notifications;
- collector profiles/privacy controls;
- external paid authentication intake;
- trusted resale workflows;
- marketplace;
- advanced analytics/reporting.

These features must not block the core provenance and ownership platform.
