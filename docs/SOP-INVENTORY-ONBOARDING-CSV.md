# SOP — Bulk inventory onboarding by CSV (operator-facing)

**Audience:** Second Chance Authenticators staff onboarding real inventory into SCA at scale.
**What it does:** creates each CSV row as a new **INTAKE** SCA item (with a system-generated public reference). It does **not** authenticate, certify, mint a QR, set ownership, or create a Shopify sale link — those remain the normal per-item steps afterward.
**Where:** Registry → **Import CSV** (requires the "create eyewear item" permission).

## CSV format
- A header row is **required**. **Allowed columns only:**
  `intake_type, brand, model_name, frame_serial, year, country_of_origin, materials, original_specifications`
- **`intake_type` is required on every row** — exactly `sce_presale` or `external_intake`.
- All other columns are optional. `year` is a number (1800–next year); text fields have length limits (brand/model/serial/materials ≤255, country ≤100, specifications ≤2000).
- **Do NOT include** a `public_ref`, `sku`, or image column, or any other column. The SCA public reference is **always generated by the system**. Unsupported columns are **flagged in preview and block the import** (so you never think discarded data was saved).
- Maximum **500 rows** per file. Split larger inventories into multiple files.

## Flow
1. **Import CSV → choose your file → Preview.** Nothing is created yet.
2. **Read the preview.** Each row is **VALID** (ready), **WARNING** (a possible duplicate — same brand/model/serial as another row or an existing item; SCA legitimately allows duplicates), or **INVALID** (cannot import — the reason is shown). Unsupported columns or >500 rows block the import until fixed.
3. **Confirm.** Valid rows are created. If there are warning rows, tick the acknowledgement box to include them; otherwise they are skipped.
4. **Result.** Each created row shows its new **SCA public reference** — use this to reconcile your source spreadsheet to SCA items.

## Reconciliation, duplicates, and re-running
- The result lists, per source row, the generated `SCA-XXXXXXXXXXXX` reference. This mapping is stored durably.
- **Re-uploading the same file never duplicates inventory:** rows already imported from that exact file are skipped. A partially completed import can be safely resumed by re-uploading the same file — only the not-yet-created rows are added.
- Nothing is ever overwritten; import only ever **creates** new items. There is no bulk edit/delete.

## Good practice
- Copy brand/model/serial from your source of record; one physical frame = one row.
- Review the WARNING rows before acknowledging them — they usually mean the item (or an identical one) is already in SCA.
